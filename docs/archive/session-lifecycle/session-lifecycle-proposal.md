# Project session exit, detach and resume — proposal

**Status:** implemented and simulated-tested under the approved recovery clarifications below. The accepted scripted UI refinement is independent of this work. See [implementation report](session-lifecycle-report.md). Text describing the pre-implementation service and proposed sequence below is retained as the reviewed design baseline.

## Operator contract

| Action | Visible result | Execution effect |
|---|---|---|
| `/detach` or Ctrl+Q | Close only this UI attachment. Reopen with `waywr` in the project. | None; authorized queue and active work continue. An unsent draft is saved first. |
| `/exit` | Show a concise checkpoint and return to the invoking shell: project, task/operation states, pending decisions, checkpoint reference, and `cd <project>; waywr resume`. If a call is still running after the bounded wait, say **“Exit requested; supervising current call, no new work will start”** rather than claiming the session has finished. | Durably pause new admissions, coordinator calls and worker permits for this project. Existing permitted calls may finish; their validated results are collected. Never implicitly cancel a task or child. |
| `waywr resume` | Resolve the current directory's project and bound release, restore the view and saved draft, explain where work stopped, reconcile receipts and answer records, then explicitly continue previously authorized work. `waywr --project DIR resume` is equivalent. | Clears the session exit pause only after project-owned identities and operations are reconciled. No new model attempt for an uncertain operation. |
| bare `waywr` | Attach to the project session; an ordinary detach reconnects to continuing work. After `/exit`, open the paused session for inspection and offer **Resume work**. | Does not silently clear an intentional exit pause. |

No `--resume` flag is needed. The current Rust dispatcher sends `resume` to the legacy run CLI. Give the no-run-argument form to the project session **before** legacy routing; keep `waywr resume RUN_ID` and explicit historical diagnostics on their existing path. A slash command is recognized only as an intentional composer command, not pasted or multiline text. Opening an exit panel never commits exit; its visible **Exit session** action does. `/detach` remains distinct from `/cancel TASK` and from the existing quiescence-gated maintenance stop.

## Four separate lifetimes and owners

The **session** is project-owned durable conversation, task queue, context selections and handoff. It can be `running`, `exit-requested`, `draining` or `paused`; a failed checkpoint or ambiguous operation is shown separately and blocks unsafe continuation. **Tasks** keep their existing independent queued, executing, awaiting-input, failed, uncertain and terminal states. **UI attachments** are disposable Herdr panes; losing one neither changes task authority nor stops the project service. The **project service** owns its lock, generation, IPC, scheduling and recovery; systemd restarts it within existing limits. Herdr owns only visible terminals. Rust owns UI/launcher presentation and the foreground Herdr client it started; Python owns session and execution transitions. No TUI database writes, model-dependent shutdown or shared Herdr shutdown.

The existing `release_maintenance.manage('stop')` first calls `_quiescent()` and refuses nonterminal tasks, reserved coordinator calls, live unreceipted workers and a live UI. It cannot implement `/exit`. The current service has no `stop_session` handler and `serve_forever()` does not drain; the reviewed plan's “stop while a worker may finish” is therefore still a gap. Implement a **project-scoped graceful stop action** in the service, then route `waywr session stop` through it. Retain `_quiescent()` for release upgrades, rollbacks and relocation. A completed graceful stop may stop only the selected project's systemd unit; the Herdr server and other projects remain untouched. A draining or uncertain session retains a responsive service for status, questions, inspection and recovery.

## Active calls and bounded shutdown

1. Commit an idempotent `stop_session` command with an expected session revision, actor, exit ID and deadline. In the same transaction record `exit-requested`, the queue pause and an event. The service generation/dispatch fence checks this intent immediately before any new permit. A concurrent already-issued permit remains an **existing** invocation, counted under its original budget. A coordinator call follows the same rule. Merely missing a heartbeat or output cannot establish that a call did not launch.
2. Reconcile active operations from immutable packet/claim/permit, verified process identity, receipt and graph state. Accept a matching completed receipt exactly once, publish its existing result through the supported workflow path, and save any decision or artifact produced. Do not enter a subsequent stage while exit pause is set. Preserve the original worker pane and output for inspection.
3. Wait up to **30 seconds** for currently executing calls to settle. This is a foreground wait limit, **not** a worker kill or retry timeout. If calls remain, return to shell with `draining`, operation identity and resume command while the project service continues monitoring. When they finish or fail, the service records their actual outcome and a final checkpoint; if execution cannot be established, mark that operation uncertain with an explicit operator action. It never fabricates a completion receipt. A failed coordinator or worker result is preserved as failed; no replacement model call is launched during exit.
4. Once no permitted operation remains in flight, atomically mark session `paused`, emit a durable event/notice, and stop only its project service through its cooperative owner path. A crash at any boundary restarts under the project unit, reads the exit intent before promotion, fences stale generations, and repeats reconciliation, not dispatch. Repeating the same exit command returns the saved state; a different payload with its ID is refused.

**Resume during exit/drain:** A resume request is valid in `exit-requested` or `draining`, including while a completed operation is being checkpointed. Serialize exit, resume and final-pause commits under the selected project's session revision lock. `resume_session` records a new monotonic session ownership generation and revision, supersedes the exit ID, and only then allows dispatch after reconciliation. The old exit's waiter may return `superseded-by-resume` but cannot publish `paused`, stop the service, or overwrite a newer checkpoint. Every final-checkpoint or shutdown action compares its saved exit ID, session revision and generation inside the same transaction immediately before commit; shutdown also rechecks after the transaction and before stopping its owned unit. If a concurrent client already committed resume, both clients observe that one authoritative outcome through events/command lookup. A lost response reuses the same command ID; a distinct stale command is refused. Test both race orders: exit wins first and resume starts a paused service, and resume wins before final checkpoint/service stop. Never let an earlier exit terminate the newly resumed service.

**Indefinitely running calls:** The 30-second foreground deadline only ends the foreground wait. A verified live process is `known-running`, and a verified live process past its operation deadline/heartbeat policy is `stalled` or `attention-required`; neither is automatically called execution-uncertain. Reuse the operation's frozen deadline and existing bounded supervisor reconciliation counters, not a new retry budget. When evidence cannot establish process/receipt identity, retain `uncertain` instead. The project service continues bounded checks and retains the visible pane. If its existing policy cannot settle the operation, persist an attention-required notice with operation ID, last verified process/heartbeat/permit/receipt evidence, reason and exact operator action. Do not silently kill, retry, adopt or replace the call; a stopped or unresponsive worker remains counted under the original authorization. Resume may show the task and accept inspection or a separately authorized targeted cancellation, but cannot dispatch the dependent stage while this operation remains unresolved. Restart retains the notice and does not reset the recovery counter.

The control loop must continue answering status, questions, cancellation and inspection during draining. A human answer saved while exiting remains durable; its dependent stage waits for `waywr resume`. If the project unit exhausts restart limits or cannot save its checkpoint, the launcher shows the last authoritative state and a durable error, never a success summary. A stopped service is started automatically by the existing paired bootstrap on resume. No model wrap-up is required; an optional separately authorized coordinator summary could supplement the checkpoint later.

**Return-to-shell gate:** the current ordinary-terminal launcher waits for its `herdr` child, while the UI is in a Herdr pane. Herdr 0.9.3's installed API schema exposes `workspace.close` and `tab.close` but no `client.detach`; closing a shared workspace or an unrelated tab is not an acceptable shortcut. The implementation should hold the identity of the foreground Herdr client it launched, observe the project-scoped exit acknowledgement through a bounded local watcher, and terminate **that owned client process only** after the UI has saved its draft and detached. Verify in an isolated Herdr server that this returns the invoking terminal to its shell without stopping the server or worker panes. If Herdr does not support this safely, stop the integration work and report the blocker before claiming `/exit` meets the contract. Inside an already-existing Herdr client, show the checkpoint in the owned pane and close only that UI attachment; do not signal the enclosing client.

## Durable checkpoint and resume selection

Canonical state continues to live in the selected project's session tables/events, run records, LangGraph checkpoints, decision/approval records, receipts, artifacts and context grants. Commit each authoritative transition when it occurs; `/exit` is not the first save. Add a compact **versioned projection**, `session/checkpoints/<revision>-<exit-id>.json` plus an atomic latest pointer, made deterministically from canonical records at significant transitions and exit/resume. Its v1 fields are project key, release/state-schema and session revision/event cursor, current goals and task IDs/statuses, active operation and budget references, accepted decisions **with rationale and source request IDs**, completed artifact IDs/hashes, unresolved questions/findings, selected context/grant IDs and version/hash references, explicit next actions, pause reason and generation. Bound it to 32 KiB; overflow becomes references to paged canonical records, never truncation of a decision. The projection is a navigational handoff, not a second approval or receipt ledger; rebuild it when missing or mismatched. An optional model summary has its own source hash and cannot overwrite canonical facts.

Resume checks project marker and release binding, starts/reconnects only that project's service, settles pending client command IDs, and compares the checkpoint revision with the live store. It takes an authoritative snapshot and event cursor, then reconciles operation identities and receipts **before** clearing the exit pause or admitting a queued task. It restores conversation via paged records, draft/outbox from project-qualified client storage, task state, decisions, open gates, budgets and artifact references. Build a bounded coordinator packet from the selected task's goals, decisions, open findings, changed artifacts and provenance; do not replay all transcripts. Frozen worker packets remain frozen. An approved candidate remains bound to its exact hash; context imported under an explicit grant keeps its original source identity and dependency mode. No unselected project registry entry becomes model context.

## Minimal contracts and implementation sequence

Use the existing IPC envelope and command ledger: add `stop_session` and `resume_session` actions, session revision/precondition and phase projection, `session.state_changed`/checkpoint events, and read-only `session.status`/checkpoint summary. Version the new persisted session/checkpoint records; document additive schema migration and refuse unknown required versions. Keep `ui.detach` display-only. Rust outbox replays the same command ID after lost replies; `command_get` resolves acceptance. Do not reuse task cancellation or approval commands for session lifecycle. No LangGraph checkpoint surgery is needed.

1. **Contract and isolated terminal proof:** add protocol fixtures and scripted UI panels for `/exit`, `/detach` and resume state labels without any production service. Verify draft saving, explicit confirmation, and the owned foreground-client return-to-shell path on an isolated Herdr server. This step may reveal a concrete Herdr blocker.
2. **Project session phase and dispatch fence:** add additive records and idempotent commands in Python, with short transactions and generation checks. Stop new permits and coordinator calls while draining. Preserve live worker receipts, questions and status availability. Focused fake-process tests cover races at permit publication, duplicate exit/resume and service restart.
3. **Checkpoint/resume:** generate/validate the deterministic handoff, reconcile first, and route no-argument `waywr resume` through the bound release. Test lost replies, stale versions, corrupt/missing projection, exact approval binding, uncertain work and bounded context packets.
4. **Installed simulated acceptance:** from an ordinary terminal and inside Herdr, run two isolated projects (including same task/run ID). Exit A with a fake call active, see the shell summary, let it finish, resume A without duplicate invocation; detach B and show it continues. Exercise both resume/final-checkpoint/shutdown race orders with two clients, lost replies, service restart, a live stalled call, ambiguous execution, release routing, other-project isolation and cleanup of only test-owned resources. Keep native calls separately gated.

The isolated scripted prototype can show the command labels, panels, summary copy, draft persistence and visual state transitions. It cannot establish service drain, actual Herdr client detach, receipt reconciliation, systemd restart or project isolation; those need installed backend and isolated Herdr/process tests. No session lifecycle behavior is implemented by the current UI refinement.

**Recommended defaults:** 30-second foreground drain wait; no model call on exit; bare `waywr` attaches without clearing an intentional exit pause, while `waywr resume` explicitly continues. These fulfill the requested distinction without adding a new approval for routine, already-authorized stages. The only technical gate is proving owned foreground-client return-to-shell through Herdr; no substantive product decision is required before that check.
